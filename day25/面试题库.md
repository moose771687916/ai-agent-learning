## 一、RAG 基础（必考！）

### Q1：什么是 RAG？

**答**：RAG（检索增强生成）= 先检索资料，再让 LLM 根据资料回答。就像开卷考试！（先查书！再答题！）

**为什么需要**：①LLM 知识有截止日期 ②LLM 会编造（幻觉） ③企业数据是私有的。

**我做过**：手写 6 环节 RAG + LangChain 版 + 高级技巧。

### Q2：RAG 的完整流程？（6 环节！）

**答**：①读文档→②切块→③向量化（embedding）→④存储（向量数据库）→⑤检索（余弦相似度取 top3）→⑥LLM 生成回答。

**我做过**：day19/milvus\_full\_rag.py 全部亲手实现！

### Q3：为什么要切块？

**答**：①LLM 上下文有限（一次看不完长文）②不切块相关性被稀释（整篇塞进去抓不住重点）。切块后只取最相关的几块，精准。

**经验**：块太小（信息不全）块太大（噪音多）。200-500 字常用。

### Q4：向量是什么？为什么 "语义相近→数字相近"？

**答**：embedding 模型把文字变成数字向量（如 BGE-M3=1024 维）。训练时让 "意思相近的文本" 向量靠近。所以 "北京天气" 和 "北京气候" 向量很近 —— 这就是语义搜索（传统数据库做不到）。

### Q5：余弦相似度怎么算？

**答**：看两个向量的夹角！0°=1（100% 像）90°=0（无关）180°=-1（相反）。



```
cos(a,b) = sum(x*y) / (|a| * |b|)
```

**坑**：查询向量必须和库里向量用同一个 embedding 模型！（换模型 = 重新建库！）

### Q6：怎么优化 RAG 效果？（高频！）

**答**（三层递进）：



1. **检索前**：分块策略（大小 / 重叠）、多查询（一个问题扩成 5 个问法分别检索合并）

2. **检索中**：混合搜索（向量找 "意思"+ 关键词找 "名字" 互补）、重排序（先粗检 20 条→rerank 精排取 3 条）

3. **检索后**：提示词约束（只根据资料回答）、加引用来源

   **我做过**：day16 全部实战！（重排序 / 混合搜索 / 多查询 / 评测！）

### Q7：重排序（Rerank）为什么有效？

**答**：向量检索是 "初筛"（快但糙）！可能把 "无关但语义近" 的排前面。rerank 用更强的模型对候选逐条精排（慢但准）。先粗检召回 20 条→精排取 3 条→质量大幅提升。

## 二、Agent 与工具调用（必考！）

### Q8：什么是 Agent？和 LLM 的区别？

**答**：LLM 只会 "说"（生成文字）！Agent 会 "做"（LLM + 工具 + 循环）！

**Agent 循环**：用户问题→LLM 思考→调工具→看结果→再思考→...→最终回答。

**我做过**：day3 Agent 主循环 + day8 三工具（天气 / 汇率 / 搜索）。

### Q9：Function Calling 是什么？

**答**：让 LLM 输出 "结构化的工具调用指令"（JSON！工具名 + 参数！），框架去执行，把结果还给 LLM。

**关键**：工具描述（description）写得好，LLM 才会调用！（描述模糊→LLM 不调！）

**我做过**：day17 全部（工具描述 / 多工具 / 并行 / 出错处理！）

### Q10：并行 vs 串行工具调用？

**答**：看依赖关系！



* 无依赖（查两个城市天气）→ 并行！（快！一次性传所有工具！）

* 有依赖（先查股票代码→再查股价）→ 串行！（前一个结果做后一个参数！）

  **LLM 怎么判断**：模型自己分析 "参数够不够"！缺参数→先调能拿到参数的工具（串行）！

  **我做过**：day17 parallel\_tool\_call.py + 依赖场景分析！

### Q11：工具调用报错 / 参数缺失怎么办？

**答**：①LLM 会再思考（换参数 / 换工具重试）②框架可设最大轮数防死循环③告诉用户 "这个我办不到"。

**关键认知**：不是 "报错终止"！是 "进入下一轮循环继续尝试"！（多轮对话式处理！）

### Q12：什么是幻觉？怎么解决？

**答**：幻觉 = LLM 一本正经编造事实！（没查过也说得跟真的一样！）

**三解法**：①接工具（查真数据！）②RAG（给资料！）③提示词约束（"不知道就说不知道"！）

**我做过**：Day 22 故意不接工具演示幻觉！Day 23 接上工具（车载 "打开空调 26 度" 真执行！）—— 对比案例！

## 三、多 Agent 协作（LangGraph！加分！）

### Q13：LangGraph 是什么？

**答**：把 Agent 流程做成【图】！节点 = 处理步骤！边 = 流转！状态（State）= 共享数据！支持条件分支 / 循环 / 并行！

**和 LangChain 区别**：LangChain = 线性的 Chain！LangGraph = 任意分支循环的图！（复杂流程用图！）

### Q14：主从模式（Supervisor）？

**答**：一个主管 Agent + 多个专家 Agent！主管理解用户问题→分配给最合适的专家（研究 / 写作 / 编辑）→汇总结果。

**我做过**：day18 langgraph\_supervisor.py（主管路由任务！）。

### Q15：人在回路（Human-in-the-loop）？

**答**：流程中间插入 "人工审核"！Agent 产出→人确认→通过才继续！（适合：发布内容 / 转账 / 重要决策！）

**实现**：中断流程→等人工输入→继续。

### Q16：为什么多 Agent 比单 Agent 好？

**答**：①每个 Agent 专注一件事（提示词简单→更准）②可并行（快）③职责分离（好维护）。

**场景**：单 Agent 多个知识库时抓不住重点！拆成多个专家 Agent 各管一个库→精准！

## 四、向量数据库（必考！）

### Q17：FAISS vs Milvus？

**答**：



|     | FAISS     | Milvus     |
| --- | --------- | ---------- |
| 定位  | 本地库（程序内嵌） | 独立数据库（服务器） |
| 数据量 | 百万级       | 亿级（分布式）    |
| 部署  | 一行代码      | Docker 三件套 |
| 适合  | 学习 / 端侧   | 企业生产       |

### Q18：FAISS 三种索引？

**答**：Flat（暴力全扫！100% 准！慢！）IVF（先分组再找！快 15 倍！）HNSW（层级跳图！快 345 倍！建索引最慢内存最大！）

**选型**：<10 万用 Flat、百万级 IVF、千万级 HNSW！

### Q19：Milvus 三件套？（面试官会眼睛一亮！）

**答**：etcd（记账！元数据！）+ MinIO（仓库！对象存储！）+ standalone（前台！查询服务！）



* etcd = 记账本（记录数据在哪）

* MinIO = 仓库（真正存文件）

* Milvus = 前台（响应查询）

  **为什么分**：可扩展（加节点）、高可用（多副本）、海量数据！

### Q20：Server 版 Milvus 的坑？

**答**：插入数据后必须 flush（提交落盘）！否则检索不到！（数据还在内存缓冲区！）

## 五、部署（必考！）

### Q21：Docker 是什么？镜像 / 容器区别？

**答**：Docker = 打包工具！镜像 = 打包好的 "环境快照"（模板！几百 MB！）容器 = 镜像跑起来的实例（运行中！）。

**类比**：镜像 = ISO 安装包！容器 = 装好的系统！

**我做过**：day20 Dockerfile 打包 Agent（python:3.12-slim！271MB！）+ docker-compose 起 Milvus 三件套！

### Q22：Docker Compose 是什么？

**答**：多容器编排工具！（一个 yml 文件定义所有服务！一条命令 `docker compose up -d` 全起！）

**我做过**：day20/docker-compose-milvus.yml（三件套编排！）

### Q23：怎么部署一个 Agent？（完整流程！）

**答**：①FastAPI 包成 API 服务→②Dockerfile 打包→③docker build 镜像→④docker run/Compose 起容器→⑤公网穿透（cpolar）/ 服务器部署→⑥日志监控（docker logs）！

## 六、多模态 + 车载（车企方向！亮点！）

### Q24：多模态 Agent 是什么？

**答**：能看（视觉模型！）、能听（ASR！）、能说（TTS！）、能想（LLM！）的 Agent！

**我做过**：day22 整合版三场景（看图问答 / 语音对话 / 图片检索！全通！）

### Q25：视觉模型怎么看图？（原理！）

**答**：不是 1 像素 = 1token！（会爆炸！）是切 patch！（16×16 像素 = 1 块 = 1token！）每块带位置编码 + 注意力机制互相看！（拼图原理！跨边界的 patch 没关系！）

### Q26：ASR/TTS 原理？

**答**：ASR（听）：声音→声学特征→文字！（识别！）TTS（说）：文字→音素→频谱→波形！（合成！）

**坑**：TTS 的 voice 参数必须是 "模型：音色" 格式！（裸写音色名报 400！）

### Q27：车载 Agent 的挑战？（车企面试加分！）

**答**：①网络差（隧道没信号）→端侧小模型 + 本地 RAG！②屏幕小→语音优先免唤醒！③嘈杂（风噪胎噪）→麦克风阵列 + 降噪！④安全第一→极简回复 + 高可靠！

### Q28：车载 RAG 怎么落地？

**答**：本地 FAISS（车机存储！离线秒答！90KB 手册知识！）+ 云端 OTA（手册更新下发！）

**我做过**：day23 FAISS 持久化版（重启不丢！秒开！）
